# 题图截图与字号规范

验收目标：不同年份、题型、题干长短的题目，正文字号一致。图片外框相同只是实现手段，不能靠逐题拉伸图片来凑齐宽度。数学上下标、分式、积分号及加粗题头保留原有排版关系。

## 参考项目 44 后采用的规则

项目 44 的 `src/README.md` 明确要求题图字高标准化；`tools/normalize_image_display.py` 使用校准后的显示宽度，并设置 HTML 数字 `width`，兼容过滤内联 CSS 的 GitHub。M2 采用相同的“字大小先统一、再确定显示比例”原则。44 中部分旧页面仍使用 `max-width:100%` 的逐图适配写法，不能将旧标签本身当作验收标准。

M2 的源题面是统一 CSS 的年度 HTML，屏幕正文字号 14.5px，公式为正文的 1.05 倍；截图倍率固定为 2，因此源正文的名义字号为 29 个图片像素。这里的名义字号是字体排版尺寸，不是每个汉字的墨迹高度。与来自不同 PDF 的扫描图不同，不能根据某张图的总宽度猜测字号或逐图凭视觉缩放。

## 截图及显示

1. 截图前必须等待公式和字体加载完成；核对题干、解答题正文与分值题头均为 14.5px，异常时中止。
2. 以 2 倍倍率逐题截图，裁除空白后只补右侧白边，得到统一 1400px 宽画布。补白不缩放、不重采样；题目超过画布宽度时报错，禁止单独缩小。
3. 所有题图使用相同显示宽度：`1400 / 29` em，数字 `width` 为 772px（16px 正文基准下四舍五入）。禁止按题目宽度设置 48em 上限，禁止单题独立适应阅读区域。
4. 支持内联 CSS 的阅读器允许横向滚动。GitHub 过滤内联样式时仍保留数字宽度；如窄屏限制图片宽度，因全部图片原始宽度和指定宽度都相同，各题将按同一比例缩小。要以约 16px 阅读，应使用足够宽的视图或打开图片放大。
5. 图片来自既有年度 HTML，不是原始试卷扫描件；统一字号不代表完成了题面内容校勘。

首次修复保留全部 385 张原图的题面像素，只补白，不重新渲染。新截图与后续构建必须沿用 `scripts/image_geometry.py` 中的统一参数。`data/image-geometry.json` 记录参数、图片高度与 SHA-256，用于发现图片更新后未同步生成的情况。

## 执行与检查

```sh
# 对现有统一源字号、2 倍截图补齐画布；不适用于未知字号的外部图片。
python3 chapters/scripts/image_geometry.py
python3 chapters/scripts/build.py
python3 chapters/scripts/check_image_geometry.py
```

如需从年度 HTML 重新截图，先运行 `python3 chapters/scripts/crop_bank.py`，再构建及检查。截图环境需安装 Chrome、仓库中的字体和 Python 依赖。

验收需要同时核对：385 张图片公共宽度与哈希；25 份 Markdown 中 385 次题图引用的数字宽度、em 比例及路径；选择题、短填空题、长题和解答题在相同显示比例下的视觉结果。不能以“文件存在”或“全部图片宽度相同”代替题面内容核对。
