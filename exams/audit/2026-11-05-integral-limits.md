# 积分上下限重叠审查（GPT）

## 原因与修复

旧版 exam.css 把 KaTeX op-symbol 的 margin-right 强制改为 0.02em，又把所有算符上下标及其嵌套 vlist 的 margin-left 清零。大积分号默认的 0.44445em 横向斜体修正被压缩，上限向左撞进积分号上端。问题可用普通上限 1、+∞、b² 和行内上限 x 稳定复现。

上下限右侧竖直对齐的需求可保留。修复保留 KaTeX 为积分号计算的 margin-right，仅将右侧带限单积分的第一层上下限 margin-left 归零，使二者在安全位置对齐。使用 integral-side-limits 标记限定范围，不干预求和、区域积分、限值内部的幂与分式。未改题目数学内容。

## 扩展审查发现（待处理）

1. `exams/assets/exam.js` 的四组预处理正则匹配的是两个反斜杠，实际 LaTeX 使用一个。因此 lim、sum、iint 的自动 limits 规范化及单积分 limits 移除规则未按预期生效。现有 HTML 部分自带 limits，遮盖了这个问题。需修正并用带/不带 limits 的输入分别核验。
2. `exams/data/2010.json` 至 `2026.json` 全部无法通过严格 JSON 解析；共 98 处 limits 只写了一个反斜杠。构建脚本直接调用 JSON.parse，故会在生成前失败。转义修复不应改变数学内容。
3. 当前 `build.cjs` 生成 exam-paper/exam-page 分页结构，现有年度 HTML 使用 exam-container 自然流结构；`exam.css` 无 exam-page 的对应版式。即使修好 JSON，直接构建也可能覆盖现有版式。需要先审查和统一生成链路，禁止为验证而覆盖现有 HTML。
4. `export-pdf.cjs` 使用 exam-page-content 检查公式边界，而现有 HTML 无该容器；标准导出脚本存在空对象访问风险。暂不执行导出。
