# PDF 方框字诊断（GPT；只读诊断）

## 当前范围

用户要求先查明方框出现的原因，不先替换字体、不只给“案”补一个字。本次未修改 HTML、CSS、字体文件或 PDF；只保存诊断。此前导出检查通过不能证明无缺字，视觉检查漏掉了题头的这类缺字。

## 已证实的事实

1. `exams/years/2016.html:77` 的源码是“请将答案写在题中的横线上”，案字为正确的 Unicode U+6848，不是输入错误或源码中的方框字符。
2. 对已交付的 `pdf/preview/math2_2016_preview.pdf` 检查字形轨迹：第2页 (313.427,80.224)—(319.530,90.393) 的字符来自 DejaVuSans-Bold，glyph ID 为0（.notdef，缺字字形）。位置对应“答案”的案。PDF 的 ActualText/文本提取仍可给出原文字，因此“文本提取得到案字”不能证明画面正确。
3. 同一份PDF第1页还存在两个 DejaVuSans-Bold 的 glyph 0，位于选择题说明的“母”和“括”处。2025样稿也有对应的3处。并非仅“案”一个字异常。
4. 项目附带的 `assets/exam-song.otf` 是精简字体，共564个字符映射，cmap内无案、母、括。
5. 遍历当前 exams 目录的全部HTML可见文本（排除script/style），得到431个不同汉字，其中20个不在该精简字体中：场复带建张批括提案母然留白码科纸自航议输。这个数是字体覆盖缺口，不等同于20个字都已在交付PDF中显示为方框；有其他系统字体时可能被补齐。
6. `exam.css` 的 `.section-title` 使用 `--font-hei`；该列表只列系统黑体/无衬线字体，没有本地 ExamSong。正文、题头和页脚的回退链并不一致，无法保证在无中文系统字体的导出环境里自给自足。
7. `scripts/export-preview.cjs` 的导出检查覆盖公式错误、题号/题数、附图、横向溢出；未检查所需字符是否有可用字形，也未检查最终PDF的 .notdef。

## 因果判断与限度

源码文字完整 → 排版时所选字体缺少字形 → 系统回退也未找到该字 → PDF写入缺字字形 → 画面显示方框。已从PDF字形、附带字体cmap和CSS回退链证实这一链路中的关键环节。

附带字体的字符集合未覆盖当前完整页面文本，静态题头/说明/导航等也有缺口。仅凭现有仓库文件不能断言当初生成子集时具体运行了哪条命令、为何漏收；未找到对应生成记录前，不把历史过程推测写成事实。
