# 处理、验证与继承

## 目录约定

每套课程均为 `pdf/` 与 `notes/` 同级，另有 `process/` 存处理记录。PDF不可覆盖，SHA-256用于确认移动后内容未变。每份PDF对应一份理解MD；“已建笔记”不等于“全部公式已核对”，阅读状态必须逐页记录。原始文件名中的年份与封面年份分别登记，禁止混版不注明。

## 每节理解应写什么

先写本课讲什么、如何分段，再写板书中具体可见的方法选择和推导路径。每条规则带物理页码；典型例题注明原标号或年份，区分“原页可见”“整理者解释”和“缺失/待核”。不以通用教材总结替代对原课的理解，不另编训练题。长课内部按方法分节，不能把几十页压成几句口号。

仅抽取文字可完成页索引和方法初筛；涉及公式、手写批注、图形、解法先后必须渲染核对。未视觉核对的页不得写作“忠实复现完成”。所有PDF物理页从1计，包含封面，不等同讲义页码。

## 接入已有真题MD

1. 从项目真题源数据读取题干、年份、原题号和章节，回看原卷题图，不凭题号猜题。
2. 先检索课程是否包含同一道题，核对题干而非只匹配年份；相同题材或同一年份都不够。
3. 找到同题时恢复原页的关键恒等变形、辅助函数、坐标选择、排除顺序等。多个原解法都存在时注明取哪一种及另外的方法，不虚构老师的唯一偏好。
4. 找不到同题时，使用已核对规则迁移，明确写“同法迁移，以下计算为GPT推导”。条件不符时不得强套。
5. 现有题单由构建脚本生成，解析必须写入可维护的数据源或独立解析文件，再由构建接入，避免重建丢失。保留所有题、分类、顺序、题图与既有提示；解析不等于已学会。
6. 复核数学正确性、板书一致性和学生能否看清第一步理由。新增解释要有用：为什么这样入手、关键步骤、成立条件、答案核对；不要把完整课程背景塞到每题下。

## 继承顺序与停止标准

后续执行先读本文件、两套课程索引、对应课笔记及来源页，再读真题匹配记录。只继续标为待核的具体页/题，已完成内容不凭印象重写。新增规则要更新来源和状态，有冲突就保留冲突并说明，不把后读材料自动当作唯一正确版本。

本次先完成结构迁移、逐课索引与理解稿，再将能核对到同题的少量已有真题接入，验证整条链路。其他真题仍明确标待匹配，不能把少量样例当成全库完成。旧自编题移入历史记录保留，不继续扩写。
